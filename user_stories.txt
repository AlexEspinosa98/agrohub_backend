Historia: Registro de usuario
- Como nuevo usuario, quiero registrarme proporcionando nombre, teléfono, identificación, correo, contraseña y asociación para poder acceder a las funcionalidades protegidas.
- Endpoint: POST /user-activity/users/register
- Ejemplo curl:
  curl -X POST \
    'https://agrohub-backend-one.vercel.app/user-activity/users/register' \
    -H 'accept: application/json' \
    -H 'Content-Type: application/json' \
    -d '{
      "name": "Alexander Espinosa",
      "phone": "3022065807",
      "identification": "1083034205",
      "email": "espinosaalexander09@gmail.com",
      "password": "contra123.",
      "association_id": 1
    }'
- Respuesta esperada (201):
  {
    "status": 201,
    "message": "usuario creado",
    "data": null
  }
- Criterios de aceptación:
  * Devuelve 201 y “usuario creado” cuando teléfono e identificación no existen.
  * Requiere `association_id`; si la asociación no existe, responde 404 “Asociación no encontrada”.
  * Si teléfono o identificación ya existen, responde 400 con detail “Teléfono o identificación ya registrados”.
  * El rol se asigna automáticamente a “user”.
  * El cliente NO envía id, role ni created_at; se generan en backend y no se devuelven (data va null).

Historia: Login de usuario
- Como usuario registrado, quiero iniciar sesión con mi teléfono o identificación y contraseña para obtener un token y mis datos básicos.
- Endpoint: POST /user-activity/users/login
- Ejemplo curl:
  curl -X POST \
    'https://agrohub-backend-one.vercel.app/user-activity/users/login' \
    -H 'accept: application/json' \
    -H 'Content-Type: application/json' \
    -d '{
      "phone_or_identification": "1083034205",
      "password": "contra123."
    }'
- Respuesta esperada (200):
  {
    "status": 200,
    "message": "login ok",
    "data": {
      "token": "<token_uuid>",
      "role": "user",
      "name": "Alexander Espinosa",
      "email": "espinosaalexander09@gmail.com"
    }
  }
- Criterios de aceptación:
  * Retorna 200 con token, role, name, email cuando credenciales son válidas.
  * Retorna 401 con “Credenciales inválidas” si teléfono/identificación o contraseña no coinciden.
  * No expone user_id ni otros campos sensibles.

Historia: Crear bitácora
- Como usuario autenticado, quiero crear una bitácora con título, descripción y fecha de actividad, para registrar mis actividades.
- Endpoint: POST /user-activity/logbooks
- Autorización: header Authorization: Token <token>
- Ejemplo curl:
  curl -X POST \
    'https://agrohub-backend-one.vercel.app/user-activity/logbooks' \
    -H 'accept: application/json' \
    -H 'Authorization: Token 1a667c8c-49e3-4a99-8a52-106315f6cac4' \
    -H 'Content-type: application/json' \
    -d '{
      "title": "string",
      "description": "string",
      "activity_date": "2026-02-02"
    }'
- Respuesta esperada (201):
  {
    "status": 201,
    "message": "bitácora creada",
    "data": null
  }
- Criterios de aceptación:
  * Requiere token; si falta o es inválido, 401.
  * Solo recibe title, description, activity_date; el user se toma del token.
  * No expone ids en la respuesta.

Historia: Listar mis bitácoras

      {

================================================================================
MÓDULO: ENCUESTA NUTRICIONAL SAN (Seguridad Alimentaria y Nutricional)
Prefijo base: /encuesta-nutricional
================================================================================

Resumen de endpoints:
  POST   /encuesta-nutricional/                        Registrar encuesta nueva
  GET    /encuesta-nutricional/                        Listar encuestas (resumen + filtros)
  GET    /encuesta-nutricional/{numero_encuesta}       Detalle completo de una encuesta
  PUT    /encuesta-nutricional/{numero_encuesta}        Corregir campos de una encuesta
  DELETE /encuesta-nutricional/{numero_encuesta}        Eliminar encuesta (soft delete)

Campos OBLIGATORIOS en POST:
  Encabezado : nombre_encuestador, cedula_encuestador, fecha_aplicacion,
               municipio, vereda_comunidad
  Cierre     : consentimiento_informado, cedula_participante

Número de formulario:
  Se genera automáticamente al guardar con formato SAN-YYYYMMDD-NNNNNN
  (fecha del día + ID secuencial de 6 dígitos).
  Ejemplo: SAN-20260429-000001

--------------------------------------------------------------------------------
DICCIONARIO DE VARIABLES — Tipos y restricciones de cada campo recibido
--------------------------------------------------------------------------------

Leyenda de tipos:
  string   → texto libre (VARCHAR en BD)
  date     → fecha en formato YYYY-MM-DD
  int      → número entero
  float    → número decimal
  bool     → true / false
  [string] → lista de strings (array JSON, se guarda como JSON en BD)
  enum     → string con valores fijos permitidos (ver columna "Valores válidos")

  OBL = campo obligatorio en POST
  OPC = campo opcional (puede omitirse o enviarse null)

--- ENCABEZADO DE IDENTIFICACIÓN ---

  Campo                  Tipo    OBL/OPC  Restricciones / Valores válidos
  ---------------------  ------  -------  -----------------------------------------------
  nombre_encuestador     string  OBL      Texto libre, máx. 255 caracteres
  cedula_encuestador     string  OBL      Texto libre, máx. 50 caracteres
  fecha_aplicacion       date    OBL      Formato YYYY-MM-DD  (ej. "2026-04-29")
  codigo_cuestionario    string  OPC      Texto libre, máx. 100 caracteres
  municipio              enum    OBL      Algarrobo | Fundación | Aracataca | El Retén
  vereda_comunidad       string  OBL      Texto libre, máx. 255 caracteres

--- SECCIÓN A — DATOS SOCIODEMOGRÁFICOS ---

  Campo                  Tipo    OBL/OPC  Restricciones / Valores válidos
  ---------------------  ------  -------  -----------------------------------------------
  nombre_participante    string  OPC      Texto libre, máx. 255 caracteres
  edad_anios             int     OPC      Entero entre 0 y 120
  sexo                   enum    OPC      Hombre | Mujer | Otro
  area_residencia        enum    OPC      Rural | Urbana
  nivel_educativo        enum    OPC      Ninguno | Primaria | Secundaria | Técnico | Universitario
  num_personas_hogar     int     OPC      Entero >= 1
  num_mujeres_hogar      int     OPC      Entero >= 0
  hay_menores_18         bool    OPC      true | false
  num_ninos_menores_5    int     OPC      Entero >= 0
  fuente_ingreso_        enum    OPC      Empleo/negocio | Ayudas del gobierno |
    principal                             Jornalero | Cría y venta de animales
  tiene_huerta_o_        bool    OPC      true | false
    animales
  jefatura_hogar         enum    OPC      Padre | Madre | Hijo/a | Abuelo/a | Varios | Otro
  estabilidad_ingreso    enum    OPC      Fijo todos los meses | Variable (temporadas) |
                                          Sin ingreso fijo

--- SECCIÓN B — ESTADO NUTRICIONAL ---

  Campo                        Tipo   OBL/OPC  Restricciones / Valores válidos
  ---------------------------  -----  -------  -----------------------------------------------
  percepcion_estado_           enum   OPC      Muy bajo | Bajo | Adecuado | Alto | Muy alto
    nutricional
  cambio_peso_no_intencional   bool   OPC      true | false
  nino_en_control_crecimiento  enum   OPC      Sí | No | N/A
  peso_kg                      float  OPC      Decimal positivo  (ej. 61.5)  — unidad: kg
  talla_cm                     float  OPC      Decimal positivo  (ej. 158.0) — unidad: cm
  circunferencia_cintura_cm    float  OPC      Decimal positivo — solo adultos >= 18 años
  perimetro_brazo_cm           float  OPC      Decimal positivo — niños 0-59m, adolescentes, adultos
  grupo_perimetro_brazo        enum   OPC      Niño <5 años | Adolescente | Adulto
  imc_calculado                float  OPC      Decimal positivo — kg/m², solo adultos >= 18 años
                                               (se puede calcular en frontend: peso/(talla_m^2))

--- SECCIÓN C — HÁBITOS Y PRÁCTICAS ALIMENTARIAS ---

  Diversidad dietética (días consumidos en los últimos 7 días):

  Campo                          Tipo  OBL/OPC  Restricciones
  -----------------------------  ----  -------  --------------------------
  dias_cereales_tuberculos       int   OPC      Entero entre 0 y 7
  dias_leguminosas               int   OPC      Entero entre 0 y 7
  dias_carnes_pescado_huevo      int   OPC      Entero entre 0 y 7
  dias_lacteos                   int   OPC      Entero entre 0 y 7
  dias_frutas                    int   OPC      Entero entre 0 y 7
  dias_verduras                  int   OPC      Entero entre 0 y 7
  dias_grasas                    int   OPC      Entero entre 0 y 7
  dias_azucares_ultraprocesados  int   OPC      Entero entre 0 y 7
  puntaje_diversidad_dietetica   int   OPC      Entero entre 0 y 8 (suma de grupos consumidos)

  Frecuencia de consumo:

  Campo                          Tipo  OBL/OPC  Valores válidos
  -----------------------------  ----  -------  -----------------------------------------
  frecuencia_frutas_semana       enum  OPC      Ninguno | 1-2 días | 3-4 días | 5-7 días
  frecuencia_verduras_semana     enum  OPC      Ninguno | 1-2 días | 3-4 días | 5-7 días
  frecuencia_bebidas_azucaradas  enum  OPC      Nunca | 1-2 veces/semana | 3-4 veces/semana | Diario

  Prácticas alimentarias:

  Campo                          Tipo      OBL/OPC  Valores válidos
  -----------------------------  --------  -------  -----------------------------------------
  comidas_por_dia                enum      OPC      1 | 2 | 3 | 4 o más
  frecuencia_comida_fuera_hogar  enum      OPC      Nunca | 1-2/semana | 3-4/semana | Diario
  proporcion_autoconsumo         enum      OPC      Nada | Poca | La mitad | La mayoría
  alimentos_preferidos           [string]  OPC      Array JSON de texto libre, máx. 5 ítems
                                                    Ej: ["Arroz", "Plátano", "Fríjol"]

--- SECCIÓN D — SEGURIDAD ALIMENTARIA (ELCSA adaptada) ---

  Campo                               Tipo  OBL/OPC  Restricciones / Valores válidos
  ----------------------------------  ----  -------  -----------------------------------------------
  preocupacion_alimentos_acabaran     bool  OPC      true | false
  alimentos_se_acabaron               bool  OPC      true | false
  adulto_omitio_comida_principal      bool  OPC      true | false
  sintio_hambre_sin_comer             bool  OPC      true | false
  puntaje_inseguridad_alimentaria     int   OPC      Entero entre 0 y 4 (suma de los 4 bool anteriores)
  clasificacion_seguridad_            enum  OPC      Seguridad alimentaria | Inseguridad leve |
    alimentaria                                      Inseguridad moderada | Inseguridad severa

  Regla de clasificación sugerida (ELCSA):
    0 respuestas "true"  → Seguridad alimentaria
    1 respuesta  "true"  → Inseguridad leve
    2-3 respuestas "true"→ Inseguridad moderada
    4 respuestas "true"  → Inseguridad severa

--- CIERRE ---

  Campo                       Tipo    OBL/OPC  Restricciones
  --------------------------  ------  -------  -----------------------------------------------
  consentimiento_informado    bool    OBL      true | false  (firma o huella del participante)
  cedula_participante         string  OBL      Texto libre, máx. 50 caracteres
  observaciones_encuestador   string  OPC      Texto libre sin límite

--- CAMPOS GENERADOS POR EL SISTEMA (no se envían en POST ni PUT) ---

  Campo            Tipo      Descripción
  ---------------  --------  -----------------------------------------------
  numero_encuesta  string    Generado automáticamente: SAN-YYYYMMDD-NNNNNN
  id               int       ID autoincremental interno de la BD
  is_active        bool      true por defecto; false al hacer DELETE
  created_at       datetime  Timestamp de creación (UTC, formato ISO 8601)
  updated_at       datetime  Timestamp de última modificación (UTC)
  deleted_at       datetime  Timestamp de eliminación; null si no fue eliminada

Historia US-07: Eliminar encuesta duplicada (soft delete)
--------------------------------------------------------------------------------
- Como coordinador, quiero desactivar una encuesta registrada por error, para que
  no aparezca en los listados sin borrar el histórico.
- Endpoint: DELETE /encuesta-nutricional/{numero_encuesta}
- Criterios de aceptación:
  * La encuesta queda en BD con is_active = false y deleted_at con timestamp.
  * No se puede consultar por GET ni modificar por PUT después del delete.
  * 404 si el numero_encuesta no existe o ya estaba eliminada.

- Ejemplo curl:
  curl -X DELETE \
    'https://backend.agroshub.online/encuesta-nutricional/SAN-20260429-000002' \
    -H 'accept: application/json'

- Respuesta esperada (200):
  {
    "status": 200,
    "message": "encuesta eliminada",
    "data": null
  }

Errores comunes del módulo
--------------------------------------------------------------------------------
  404 - Encuesta no encontrada:
        {"detail": "Encuesta no encontrada"}

  400 - PUT sin campos:
        {"detail": "Nada para actualizar"}

  422 - Campo obligatorio faltante en POST (ejemplo: falta municipio):
        {"detail": [{"loc": ["body", "municipio"], "msg": "field required", "type": "value_error.missing"}]}

  422 - Valor fuera de rango (ejemplo: edad_anios: 150):
        {"detail": [{"loc": ["body", "edad_anios"], "msg": "ensure this value is less than or equal to 120", "type": "value_error.number.not_le"}]}
